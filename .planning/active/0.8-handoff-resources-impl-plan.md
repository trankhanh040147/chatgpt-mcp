## Contract summary

```text
handoff_submit_result({
  taskId,
  result,              // required, non-empty
  metadata?,
  artifacts?: [{       // optional, max 20
    path,              // workspace-relative POSIX
    content,           // complete final UTF-8 body
    mode?: "create" | "overwrite"
  }]
})
```

**Layers:** Schema (shape) → Runtime (security/state/bytes/batch) → Tool description (capability) → `submitPolicy.writeback` (decisions) → ADR-010 (full semantics).

## Phase 1 — Transactional runtime (must-fix)

**File:** [`src/tasks/result-artifacts.ts`](../../src/tasks/result-artifacts.ts)

Refactor `writeResultArtifacts()`:

1. **Validate all** — no target mutation (paths, caps, full-body secret scan, containment, mode/exists checks)
2. **Stage** — temps only
3. **Commit batch** — overwrite: backup → rename; create: `open(path, 'wx')`
4. **Rollback on handled failure** — restore overwrites, delete creates
5. Return manifest only after full batch success

**Pragmatic guarantee (confirmed):** validation failure → zero writes; handled commit failure → rollback before error. ADR documents crash/rollback-fail/concurrency limits.

**GitNexus:** `impact({ target: "writeResultArtifacts", direction: "upstream", repo: "chatgpt-mcp" })` before edit — risk LOW, callers: `submitResult`, `test-result-artifacts`.

**Tests** ([`scripts/test-result-artifacts.ts`](../../scripts/test-result-artifacts.ts)):

- Mid-batch failure → prior files unchanged / restored
- Create collision / TOCTOU
- Secret beyond 512 KiB (after Phase 2)

## Phase 3 — MCP Writeback Contract (merged old Phase 3 + 4)

Single pass: model guidance ↔ server rejection loop.

### 3A — Error contract

**File:** [`src/mcp/tools/index.ts`](../../src/mcp/tools/index.ts)

Add `artifactErrorContent(code, safePath?)` returning `{ content, isError: true }`.

| Error | Delivery |
|-------|----------|
| `HandoffFileError` (validation/business) | `isError: true`, code + safe path/index only |
| Unexpected I/O / bug | Generic `ARTIFACT_WRITE_FAILED` throw |

Wire `handoff_submit_result` handler — replace bare `taskService.submitResult()` throw path.

**Do not** map create collision to overwrite suggestion in error text.

### 3B — Model guidance

**File:** [`src/mcp/worker-policy.ts`](../../src/mcp/worker-policy.ts)

- Add compact `WRITEBACK_POLICY` (decision tree + batch/rejection rules — see spec §5.2)
- Replace `SUBMIT_RESULT_TOOL_DESCRIPTION` with concise capability text (limits 20/32/128, full-content, modes, batch semantics — no implementation details)

**File:** `index.ts` — USER tasks only:

```typescript
submitPolicy: {
  ...SUBMIT_POLICY,
  writeback: WRITEBACK_POLICY,
  lateSubmitAccepted: ...,
}
```

SYSTEM_PROBE tasks: no writeback policy.

**Post-change:** `npm run build && gptmcp restart`

### 3C — MCP annotations (nice-to-have, same PR if trivial)

Fix `handoff_submit_result` annotations:

```typescript
readOnlyHint: false,
destructiveHint: true,
idempotentHint: false,
openWorldHint: false,
```

### 3D — Contract tests

**New:** `scripts/test-writeback-contract.ts` (+ npm script)

Assert without live worker:

- USER `get_task` payload includes `submitPolicy.writeback`
- Policy contains complete-content rule + create-collision guidance (no overwrite retry)
- Tool description mentions 20 / 32 MiB / 128 MiB (not "10 files")
- `handoff_submit_result` returns `isError: true` for simulated `HandoffFileError`
