## 1. Problem

Operators lose time when registry, SQLite, CDP tabs, and broker memory diverge. URL change today requires file edit + `sqlite` + **broker restart** (`RESTART_REQUIRED`). v0.6 delivers **lite control plane**: durable operations + reconciler + broker HTTP, extending the **existing** dashboard.

## 4. `worker_operations` journal

### 4.1 Schema (SQLite migration)

```sql
CREATE TABLE worker_operations (
  id TEXT PRIMARY KEY,
  worker_id TEXT NOT NULL,
  kind TEXT NOT NULL,           -- ASSIGN_URL | CREATE_CHAT | KILL_RECREATE | ...
  state TEXT NOT NULL,          -- PENDING | RUNNING | VERIFYING | SUCCEEDED | FAILED
  payload_json TEXT NOT NULL,
  attempt INTEGER NOT NULL DEFAULT 0,
  last_error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_worker_operations_active
  ON worker_operations(worker_id, state);
```

### 4.2 Operation states

```text
PENDING    → accepted, not yet stepped
RUNNING    → reconcile stepping (registry/db/broker)
VERIFYING  → system probe in flight
SUCCEEDED  → terminal ok
FAILED     → terminal (operator retry creates new op or retry endpoint)
```

### 4.3 Idempotent reconcile steps (per kind)

URL mutation pipeline — **ensure** not **do**:

```text
ensureRegistry(desiredUrl)     -- upsert if mismatch
ensureDbState(desiredUrl)      -- worker_url, tasks_on_chat reset, CONSENT_REQUIRED
ensureBrokerBinding(desiredUrl)-- broker HTTP rebind if mismatch
ensureVerification(workerId)  -- SYSTEM_PROBE until READY or FAILED
```

On crash between steps: restart reconciler reads op in PENDING/RUNNING/VERIFYING → resume from first failing ensure.

### 4.4 API surface (imperative → enqueue)

```http
POST /ops/workers/assign-url     { workerId, workerUrl, confirm: "ASSIGN w1" }
POST /ops/workers/create-chat    { workerId, confirm: "CREATE w1" }
POST /ops/workers/kill-recreate  { workerId, mode, workerUrl?, confirm: "KILL w1" }
POST /ops/workers/retry-verify   { workerId }
POST /ops/workers/set-enabled    { workerId, enabled, confirm }
POST /ops/workers/add            { confirm: "ADD WORKER" }
```

All: loopback origin + CSRF (same as `/ops/recover`). Response includes `operationId`.

## 5. Broker Control HTTP (:8788)

| Var | Default |
|-----|---------|
| `HANDOFF_BROKER_OPS_PORT` | `8788` |
| `HANDOFF_BROKER_OPS_TOKEN` | required when ops server enabled |

Bind `127.0.0.1` only. Auth: `Authorization: Bearer <token>`.

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/broker/status` | bindings, cdpEndpoint, connectionGeneration, unboundRegistryIds |
| GET | `/broker/probe-session?workerId=` | session ready on bound page |
| POST | `/broker/rebind` | `{ workerId, workerUrl }` |
| POST | `/broker/unbind` | `{ workerId }` close page, release binding |
| POST | `/broker/create-chat` | `{ workerId, bootstrapMessage? }` on shared context |

Broker methods (internal): `rebind`, `unbind`, `createChat`, `getStatusSnapshot`, `probeSession`.  
`create-chat.ts` → `createWorkerChatOnContext(context, opts)` — no `connectOverCDP` in Worker Ops path.

### Fleet startup (G3)

- Parse invalid registry → broker process exit (configuration error).
- Per worker: bind failure → worker condition BLOCKED/UNBOUND; **do not** fail entire broker if other workers bindable.
- Relax `BrowserBroker` constructor: optional workers without URL → skip bind until reconciler provides URL.

## 6. System probe (verification)

### 6.1 Task schema migration

```sql
ALTER TABLE handoff_tasks ADD COLUMN task_class TEXT NOT NULL DEFAULT 'USER';
ALTER TABLE handoff_tasks ADD COLUMN target_worker_id TEXT NULL;
```

Values: `USER` | `SYSTEM_PROBE`.

### 6.2 Claim semantics

```text
SYSTEM_PROBE with target_worker_id = w1
  → may claim on w1 even when readiness_reason = CONSENT_REQUIRED

USER
  → existing readinessBlocksClaim rules
```

No generic `ClaimPolicy` in v0.6.

### 6.3 Probe task

```ts
createTask({
  type: "second_opinion",
  taskClass: "SYSTEM_PROBE",
  targetWorkerId: workerId,
  prompt: `CREATE_WORKER_CANARY=${token}`,
  cursorConversationId: `probe-${operationId}`,  // domain metadata only
});
```

Success: exact line match → `setReadinessReason(workerId, null)`, op → SUCCEEDED.  
Retry: `HANDOFF_WORKER_OPS_PROBE_ATTEMPTS`, interval, timeout `CREATE_WORKER_CANARY_MS`.

## 7. Health conditions (lite)

Extend existing `deriveWorkerIndicators` / `/workers` — do not replace dashboard indicator UX.

### 7.1 Condition types

`PROCESS` · `BROKER` · `BINDING` · `URL` · `SESSION` · `MCP`

Each: `status` TRUE/FALSE/UNKNOWN, `reason`, `message?`, `observedAt`.

### 7.2 Aggregate

```text
READY | DEGRADED | BLOCKED | OFFLINE | UNKNOWN
```

Plus `recommendedAction`: `NONE` | `RETRY_VERIFY` | `RECREATE_CHAT` | `LOGIN_CHATGPT` | `START_BROKER` | `ASSIGN_URL`

### 7.3 API

```http
GET /workers/health   # workers + conditions + recommendedAction per row
```

Dashboard poll: health 10s (tasks/workers may stay 2s or merge into health).

## 9. Implementation phases

| Phase | Scope | Exit |
|-------|--------|------|
| **A** | Broker control HTTP + ADR-009; status-api can `GET` broker status | Broker owns Worker Ops CDP path |
| **B** | `worker_operations` table + reconciler (startup + periodic) | Simulated crash resumes op (M6–M7) |
| **C** | Assign/rebind pipeline via enqueue + ensure steps | Assign URL without broker **process** restart |
| **D** | `SYSTEM_PROBE` migration + claim bypass + ensureVerification | CONSENT → probe → READY (M1) |
| **E** | Create/recreate + health conditions + dashboard modals | M2–M3 UX on existing dashboard |
| **F** | Dynamic fleet (enabled, add worker) + G3 startup isolation + hardening | M4–M5, M8, M10 |

**Order rationale:** C before D — prove durable mutation + broker convergence before debugging MCP consent.
