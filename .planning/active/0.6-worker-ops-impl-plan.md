## 1. Problem statement

Operators lose time when:

1. Worker chat URL changes (new account, new chat) but **registry ≠ CDP tab ≠ `.env`**.
2. `CONSENT_REQUIRED` blocks claims after URL commit — requires **manual DB edit**.
3. `SESSION_LOST` leaves tasks **QUEUED** while `/worker` still shows READY (stale heartbeat).
4. Registry lists workers **without CDP tab binding** → perpetual `No broker binding`.

v0.6 makes recovery **one dashboard flow** with auto-canary clearing consent.

## 2. Architecture (target)

```text
Dashboard (loopback)
    │  GET /workers/health  (poll)
    │  POST /ops/workers/*  (mutations, CSRF)
    ▼
status-api (:8787)
    │  WorkerOpsService
    │  TaskRepository / topology writer
    ▼
browser-broker (CDP owner)
    │  rebindWorker(id, url) / openTab / closeTab
    │  runCanary(workerId)  → dispatch CREATE_WORKER_CANARY task
    ▼
CDP Chrome (N tabs ↔ N registry workers)
```

**Config SSOT:** `HANDOFF_WORKERS_FILE` (default `data/workers.a1s.json`).  
**Legacy:** if no workers file, synthesize single worker from `.env` (`env-single`) — dashboard shows one row `default`.

## 3. Health model

### 3.1 Probe dimensions (per worker id)

| Probe | Source | Healthy when |
|-------|--------|--------------|
| `pid_alive` | `worker_state.pid` + `kill(0)` | process alive |
| `heartbeat_fresh` | `last_seen_at` vs `HANDOFF_WORKER_STALE_MS` | not stale |
| `cdp_reachable` | broker `isHealthy()` + CDP `/json/version` | CDP up |
| `tab_bound` | broker binding map has `workerId` | page attached |
| `tab_url_match` | `page.url()` chat id == registry `workerUrl` | same `/c/…` |
| `session_ready` | `ChatGptBrowser.ensureSessionReady()` on bound page | logged in |
| `readiness_clear` | `readiness_reason` null | not blocked |
| `mcp_canary_recent` | last canary task COMPLETED within TTL (optional chip) | consent proven |

Aggregate: `healthScore` = `ok` | `degraded` | `bad` (worst probe wins).

### 3.2 API

```http
GET /workers/health
```

Response extends `/workers` with `probes: Record<string, boolean|string>` and `healthScore` per worker.

Poll interval dashboard: **10s** default (config `HANDOFF_DASHBOARD_HEALTH_POLL_MS`).

### 3.3 Broker status

```http
GET /broker/status   # new, loopback only
```

Returns: `cdpEndpoint`, `connectionGeneration`, `bindings: [{ workerId, chatId, pageUrl, generation }]`, `unboundRegistryIds[]`.

## 4. Worker lifecycle operations

All mutations: existing **ops gate** (`requireOpsBrowser`, CSRF from `/ops/session`), typed confirm for destructive actions (pattern: `RECOVER` / `FAIL`).

### 4.1 Assign URL

```http
POST /ops/workers/assign-url
{ "workerId": "w1", "workerUrl": "https://chatgpt.com/c/…", "confirm": "ASSIGN w1" }
```

**Steps (server-side, single transaction where possible):**

1. `assertWorkerIdle(workerId)` — refuse if in-flight task.
2. Validate URL (`sanitizeChatUrl`, `/c/<id>` required).
3. `upsertWorkerRegistryEntry` (atomic file lock).
4. `repo.commitChatRotation` → `CONSENT_REQUIRED` + reset `tasks_on_chat` when URL identity changes (reuse rotation DB helper).
5. Call broker `rebindWorker(workerId, newUrl)` — navigate tab or allocate new tab from pool.
6. Start **auto-canary job** for `workerId` (see §5).
7. Audit log + dashboard toast with job id.

**Does not** restart broker process (broker in-process rebind).

### 4.2 Create new chat (CDP)

```http
POST /ops/workers/create-chat
{ "workerId": "w1", "confirm": "CREATE w1" }
```

1. `assertWorkerIdle`.
2. Broker runs `createWorkerChat({ cdpEndpoint })` under UI mutex (reuse `src/browser/create-chat.ts`).
3. Capture `workerUrl` from result.
4. Same pipeline as Assign URL from step 3 onward.

Optional body: `{ "bootstrapMessage": "…" }` for debugging.

### 4.3 Kill + recreate binding

```http
POST /ops/workers/kill-recreate
{ "workerId": "w1", "mode": "assign" | "create", "workerUrl?": "…", "confirm": "KILL w1" }
```

1. `assertWorkerIdle`.
2. Broker: close tab / release binding (do not quit Chrome).
3. If `mode=create` → create chat; else require `workerUrl`.
4. Registry + rotation commit + rebind + auto-canary.

Used by SESSION_LOST heal flow.

### 4.4 Enable / disable worker (dynamic N)

```http
POST /ops/workers/set-enabled
{ "workerId": "w2", "enabled": false, "confirm": "DISABLE w2" }
```

- **Disabled:** excluded from claim scheduling; broker may close tab; remains in registry with `enabled: false` (new optional field in JSON **or** separate `disabledWorkers` in DB — prefer **registry field** `enabled?: boolean`, default true).
- Prevents w2/w3 ERROR when only one tab desired.

### 4.5 Add worker slot

```http
POST /ops/workers/add
{ "confirm": "ADD WORKER" }
```

- `nextWorkerId(existing)` → append entry with empty `workerUrl` placeholder **or** immediate create-chat flow.
- Broker attempts bind when URL set.

## 5. Auto-canary (CONSENT automation)

### 5.1 Behavior

After URL assign/create/kill-recreate:

1. Set `readiness_reason = CONSENT_REQUIRED` (already from rotation commit).
2. Background **canary runner** (status-api timer or broker callback):
   - Create task `type=second_opinion`, prompt = `CREATE_WORKER_CANARY=<token>`, `cursorConversationId=worker-ops-canary-<workerId>`.
   - Broker dispatches only on **that worker's** binding (scheduler must route by `lease_owner` / worker id).
   - Poll until `COMPLETED` | `FAILED` | `TIMED_OUT` | max attempts.
3. On **COMPLETED** with exact canary line:
   - `repo.setReadinessReason(workerId, null)`
   - `repo.clearWorkerError(workerId)`
   - Log `WORKER_OPS_CANARY_OK`.
4. On failure: keep `CONSENT_REQUIRED`, surface last error on dashboard (“Approve MCP write tools in chat, then Retry canary”).

### 5.2 Retry policy

| Setting | Default |
|---------|---------|
| `HANDOFF_WORKER_OPS_CANARY_ATTEMPTS` | 12 |
| `HANDOFF_WORKER_OPS_CANARY_INTERVAL_MS` | 15000 |
| Canary timeout | `CREATE_WORKER_CANARY_MS` (300000) |

Manual retry button: `POST /ops/workers/retry-canary { workerId }`.

**No silent infinite loop** — after max attempts, stop and show `CANARY_FAILED`.

Reuse canary prompt from `scripts/create-worker.ts` (`CREATE_WORKER_CANARY=…`).

### 5.3 ChatGPT operator steps (unchanged)

Auto-canary **does not** approve MCP UI — operator must approve write tools once in the new chat. Canary detects when approval works.

## 6. SESSION_LOST auto-heal

### 6.1 Detection

Health poll sets `probe.session_ready = false` and `status === SESSION_LOST` → dashboard row **red** + banner.

### 6.2 UI

Modal:

```text
Worker w1 lost ChatGPT session.
[ Cancel ]  [ Kill & recreate chat… ]
```

On confirm → `POST /ops/workers/kill-recreate` with `mode=create` (or operator picks assign URL in advanced panel).

**No auto-trigger** without modal (grilling decision).

## 7. Broker changes

### 7.1 Dynamic bind map

- On start: read registry → for each **enabled** worker with valid URL, bind tab (existing `attachAndBindAll`).
- Workers in registry without URL: state `PENDING_URL`, not ERROR.
- Workers enabled but bind fails: `BIND_FAILED` with actionable error.

### 7.2 `rebindWorker(workerId, workerUrl)`

- If binding exists: navigate page to new URL (or replace page).
- Update `chatOwners` map.
- Increment binding `generation`; notify worker actors via existing broker callback.

### 7.3 Multi-tab on one CDP

- One registry entry → one dedicated tab (current A1-S model).
- Adding workers adds tabs on **same** `cdpEndpoint` (already supported if URLs unique).
- Remove hard assumption of exactly 3 workers in UI.

### 7.4 IPC option (if broker separate process)

**Preferred v0.6:** status-api and broker stay in **same stack** as today (`start-broker-stack.sh`) — ops calls broker handle in-process via shared module export.

If broker is separate PID only: add loopback HTTP on broker `POST /broker/rebind` — **defer** unless split process required.

## 11. Security

- All `POST /ops/workers/*`: loopback origin + CSRF (same as `/ops/recover`).
- Typed confirm tokens include **worker id** to prevent wrong-target ops.
- No mutation via GET.
- `workerUrl` sanitized — https chatgpt.com only.
- Audit log: `WORKER_OPS_*` events in `handoff.log` (no secrets).

| Risk | Mitigation |
|------|------------|
