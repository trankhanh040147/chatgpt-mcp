# 0.6 — Worker Ops & Dashboard

**Status:** ACTIVE · **Lifecycle:** SHIP-BAR  
**Impl plan:** [0.6-worker-ops-impl-plan.md](./0.6-worker-ops-impl-plan.md)  
**ADR:** [ADR-008](../decisions/ADR-008-worker-ops-dashboard.md)

## Goal

Operator can **see worker health** and **recover from SESSION_LOST / URL / CONSENT** from the dashboard — without hand-editing `.env`, `workers.a1s.json`, `sqlite`, or guessing broker restarts.

**Depends on:** 0.4 dashboard, 0.3 create-worker, 0.5 rotation readiness model.  
**Unblocks:** 0.7 Handoff Resources E2E (attach + CONSENT + multi-tab broker).

## Pain today (why v0.6 first)

| Pain | Cause |
|------|--------|
| Sửa `CHATGPT_WORKER_URL` trong `.env` không đủ | Broker dùng `HANDOFF_WORKERS_FILE` |
| `CONSENT_REQUIRED` block claim | URL change → fail-closed; manual `sqlite` clear |
| Task stuck `QUEUED` | Worker SESSION_LOST / readiness / dead pid |
| w2/w3 ERROR | Registry có worker không bind tab |

## Frozen decisions (grilling 2026-08-30)

| Decision | Choice |
|----------|--------|
| Deployment | **Broker-primary** — `workers.a1s.json`; `.env CHATGPT_WORKER_URL` legacy alias for `default` only |
| Worker count | **Dynamic** — N entries in registry ↔ N tabs on one CDP; không hardcode w1–w3 |
| Dashboard actions | **Assign URL** + **Create new chat** (CDP) |
| After URL change | **Auto-canary loop** until pass → clear `CONSENT_REQUIRED` |
| Kill | **Kill binding + recreate** path |
| SESSION_LOST | **Auto-heal** với **confirm modal** trên dashboard (không silent loop) |
| Health | Poll + chips; SESSION_LOST heal có confirm |

## Non-goals (v0.6)

- Claude host · ZIP/context-pack · MCP `resource_link` transport
- SaaS / SSO / hosted dashboard
- Auto-login ChatGPT
- Silent auto-heal without operator confirm
