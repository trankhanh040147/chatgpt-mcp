# 0.6 — Worker Control Plane (Ops & Dashboard)

**Status:** ACTIVE · **Lifecycle:** SHIP-BAR · **Spec frozen:** 2026-08-30  
**Impl plan:** [0.6-worker-ops-impl-plan.md](./0.6-worker-ops-impl-plan.md)  
**ADR:** [ADR-008](../decisions/ADR-008-worker-ops-dashboard.md) · [ADR-009](../decisions/ADR-009-runtime-cdp-ownership.md)

## Goal

**Lite control plane:** imperative dashboard/CLI commands → durable `worker_operations` → idempotent reconcile → broker-exclusive CDP. Operator recovers URL / CONSENT / SESSION_LOST from **existing** dashboard (`/dashboard/`) without `sqlite`, hand-editing registry, or broker restart for normal URL ops.

**Depends on:** 0.4 dashboard, 0.3 create-worker, 0.5 rotation readiness.  
**Unblocks:** 0.7 Handoff Resources — contract: worker `READY` → claim `USER` task → resource delivery → dispatch (no new lifecycle in v0.7).

## Baseline (already shipped)

Extend **dashboard 0.3–0.4** on `http://127.0.0.1:8787/dashboard/` — workers cards, indicators, recover/fail-task, topology. v0.6 adds worker mutation + broker-aware health, not a new UI shell.

## Pain today

| Pain | Cause |
|------|--------|
| `.env` URL ≠ registry ≠ tab | Broker uses `HANDOFF_WORKERS_FILE` |
| `CONSENT_REQUIRED` | Manual `sqlite` after URL change |
| `RESTART_REQUIRED` after rotate | CLI commits file+DB; broker bind only on restart |
| Task `QUEUED` | SESSION_LOST / stale heartbeat / readiness |
| w2/w3 ERROR | Registry worker without binding; strict broker boot |

## Frozen architecture (2026-08-30)

```text
Dashboard / CLI → imperative POST /ops/workers/*
      ↓
status-api → enqueueOperation()
      ↓
worker_operations (durable)
      ↓
reconcile() — ensureRegistry / ensureDb / ensureBroker / ensureVerification
      ↓
Registry file + SQLite + Broker :8788 + SYSTEM_PROBE → READY
```

**Imperative outside, reconciled inside.** No `WorkerSpec`, no PATCH API, no saga framework in v0.6.0.

## Ship invariants

| ID | Invariant |
|----|-----------|
| I1 | Successful URL mutation: `CONSENT_REQUIRED` → system probe → `READY`; **normal dashboard flow never sets `RESTART_REQUIRED`** |
| I2 | B1: broker owns runtime CDP mutations while running ([ADR-009](../decisions/ADR-009-runtime-cdp-ownership.md)) |
| I3 | Registry parse invalid → broker may fail start; **one bad worker → BLOCKED, fleet continues** |
| I4 | System probe via `task_class=SYSTEM_PROBE` + `target_worker_id` — not `cursor_conversation_id` hacks |
| I5 | Reconcile steps are **idempotent** (`ensureX`, not blind `doX`) |

## Deferred (not v0.6.0)

`PATCH /workers`, `WorkerSpec`, managed vs pinned chat, generic `ClaimPolicy`, `WorkerVerifier` framework, event sourcing, WebSockets, separate controller process.
