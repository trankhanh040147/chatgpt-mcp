### 3.2 Composer attach module (`src/browser/composer-attach.ts`)

```ts
export type AttachmentFailureReason =
  | "INPUT_NOT_FOUND"
  | "UPLOAD_TIMEOUT"
  | "CHIP_MISMATCH"
  | "UPLOAD_REJECTED";

export type PreparedResource = {
  fileId: string;
  displayName: string;
  status: "attached" | "failed";
};

export type PrepareResult =
  | { ok: true; attached: PreparedResource[] }
  | {
      ok: false;
      expected: string[];
      observed: string[];
      reason: AttachmentFailureReason;
    };

/** Snapshot paths on disk — not workspace paths */
export async function attachSnapshotFiles(
  page: Page,
  files: readonly HandoffTaskFile[],
): Promise<PrepareResult>;
```

**Algorithm:**

1. `findComposerFileInput(page)` — scoped to composer, prefer visible/hidden `input[type=file]`
2. `input.setInputFiles(files.map(f => f.snapshotPath))` (Playwright → CDP `DOM.setFileInputFiles`)
3. If no input: `openAttachmentMenu(page)` → wait for input → setInputFiles
4. Poll attachment UI state (chips / upload indicators) with timeout
5. `verifyAttachments(expected, observed)` — per-file matcher (see §3.3)
6. Return structured `PrepareResult`

**Selectors:** add to `src/browser/selectors.ts`; comment fragility.

### 3.3 Chip matcher (`src/browser/attachment-match.ts`)

export function matchesAttachment(

### 3.4 Thin transport stub (`src/transport/native-attachment.ts`)

Optional in PR #4 if time — full worker wiring is PR #5.

```ts
export interface ResourceDeliveryTarget {
  attachSnapshotFiles(
    files: readonly HandoffTaskFile[],
  ): Promise<PrepareResult>;
}

export class NativeAttachmentTransport {
  constructor(private target: ResourceDeliveryTarget) {}
  async prepare(files: readonly HandoffTaskFile[]): Promise<PrepareResult> {
    if (files.length === 0) return { ok: true, attached: [] };
    return this.target.attachSnapshotFiles(files);
  }
}
```

`ChatGptBrowser` implements `ResourceDeliveryTarget` by delegating to `composer-attach.ts`.

## 4. PR #5 — Worker integration + dispatch fence

**Research before coding:** read [ADR-004](../decisions/ADR-004-dispatch-fence-vs-attachment.md).

### 4.1 Reorder `src/browser/worker.ts`

**Current (wrong for attach retry):**

```text
markDispatchStarted → waitIdle → withUiWrite → submitTaskId
```

**Target:**

```text
openWorkerConversation()
waitUntilComposerIdle()
withUiWrite:
  assertBindingFresh()
  prepared = await transport.prepare(task.files ?? [])
  if (!prepared.ok) throw ResourceAttachError(prepared)
  markDispatchStarted()          // fence HERE
  submitTaskId(task.id)
```

Pre-fence attach failure → `markDispatchFailed(..., { lease opts })` → **requeue**.

### 4.2 Error type + logging

```ts
class ResourceAttachError extends Error {
  constructor(public readonly result: Extract<PrepareResult, { ok: false }>) {}
}
```

Events:

```text
RESOURCE_ATTACH_STARTED
RESOURCE_ATTACH_VERIFIED
RESOURCE_ATTACH_FAILED  reason=CHIP_MISMATCH|...
```

### 4.3 Duplicate chip / retry policy

- No in-pass retry after partial attach (duplicate chip risk)
- Requeue whole task; next worker pass starts clean
- Matcher must not accept stale chips unless they match an **expected** name for **this** task

**Exit PR #5:**

- [ ] Fail-closed: files requested + attach fail → no TASK_ID
- [ ] Pre-fence attach fail requeues (not TIMED_OUT)
- [ ] Integration test or scripted mock for worker branch (if feasible)
