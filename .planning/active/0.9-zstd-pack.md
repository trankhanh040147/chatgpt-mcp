## Goal

tar.zst is a **packing adapter on the native path**, not a new transport and not MCP pull.

- **Inbound:** `files[]` → runtime packs at dispatch → **one** composer chip.
- **Outbound:** `archive` (tar.zst) XOR `artifacts[]`; extract under writeback guards.

**No silent MCP fallback.** Attach/extract/pack failure fails closed.

## Architecture

```text
handoff_create_task(files[])     # max 100 paths
  → registerTaskResourcePaths

worker dispatch:
  materializeResourcesForArchivePack → PreparedResource[] (RAM)
  → packTar (pax, regular files only) → zstd (1 frame, window ≤ 8 MiB)
  → if compressed > 64 MiB → PACK_COMPRESSED_TOO_LARGE
  → setInputFiles([{ name: handoff-{taskId}.tar.zst, buffer }])
  → verify exactly 1 chip
  DISPATCH_STARTED

handoff_submit_result:
  artifacts[]     XOR     archive { format: "tar.zst", encoding: "base64", data }
       │                         │
       │                         ├─ base64 preflight size → canonical decode
       │                         ├─ bounded zstd stream (window + uncompressed)
       │                         ├─ tar allowlist + pax effective-path + EOF
       │                         ├─ validate ALL members (no disk yet)
       │                         └─ upsert batch (validate → commit → rollback)
       └─ v0.8 writeResultArtifacts (max 20)
```

**Security boundary:**

```text
64 MiB wire → bounded zstd decoder → bounded tar parser
  → ≤100 validated text members → transactional writeback
```

No step may trust FCS / pax size / tar size fields as a substitute for enforced byte counters.

## Caps (tar.zst path)

| Cap | Symbol | Value |
|-----|--------|-------|
| Members | `MAX_ARCHIVE_MEMBERS` | **100** |
| Per-member body | `MAX_MEMBER_BYTES` | **64 MiB** |
| Uncompressed tar stream | `MAX_UNCOMPRESSED_BYTES` | **64 MiB** |
| Compressed payload | `MAX_COMPRESSED_BYTES` | **64 MiB** |
| Zstd window / single-segment FCS | `MAX_ZSTD_WINDOW` | **8 MiB** |
| `artifacts[]` | — | 20 / 32 MiB / 128 MiB |

**Uncompressed accounting:** running counter on **tar stream bytes leaving the zstd decoder**; abort before byte `MAX_UNCOMPRESSED_BYTES + 1`. Member body additionally capped at `MAX_MEMBER_BYTES` after pax `size=`.

**Compressed vs uncompressed are independent.** Plain members summing to 64 MiB may still fail pack with `PACK_COMPRESSED_TOO_LARGE`. Fail closed — no drop, no fallback.

## Decoder / extractor invariants (normative)

### Zstd — window rule (hardened)

RFC 8878: when `Single_Segment_Flag=1`, `Window_Size = Frame_Content_Size`. Therefore **single-segment is not an exception** to the 8 MiB window:

```text
if singleSegment:
    require FCS present
    require FCS <= MAX_UNCOMPRESSED_BYTES
    require FCS <= MAX_ZSTD_WINDOW          # 8 MiB — same memory bound
else:
    require Window_Size <= MAX_ZSTD_WINDOW
```

Producer **must** emit a **windowed** frame (`Single_Segment_Flag=0`) with `Window_Size ≤ 8 MiB` for archives whose tar stream may exceed 8 MiB (up to 64 MiB). Single-segment is only valid for tiny packs with FCS ≤ 8 MiB.

Also:

1. **Exactly one** Zstandard frame. Reject concatenated frames, trailing garbage, **skippable frames**, dictionaries (`dictID != 0`).
2. **Do not trust FCS alone** for allocation — stream-enforce `MAX_UNCOMPRESSED_BYTES`.
3. Streaming bound: abort before decompressed byte `MAX_UNCOMPRESSED_BYTES + 1`; must not materialize full tar then check.

### Base64 (`archive.data`)

```text
1. Syntax/padding check (RFC 4648 canonical; no whitespace)
2. Derive decoded size from encoded length (preflight) — reject if > MAX_COMPRESSED_BYTES
   WITHOUT allocating the full decoded buffer for oversized inputs
3. Decode; reject if decoded length > MAX_COMPRESSED_BYTES
```

~85 MiB base64 is magnitude only — not an MCP host guarantee. Host reject → fail closed.

### Tar entry allowlist

**Allowed:** regular file (`'0'` / `'\0'`); pax `'x'` only.  
**Rejected:** `'g'`, symlink, **hardlink**, directory, devices, FIFO, GNU sparse, unknown.

**Effective path** = path **after** pax `path=`; then canonicalize (POSIX `/`, no `\`, no `..`, no absolute, no `./`, no NUL). Duplicate effective paths reject. Extension allowlist = `isAllowedResourceExtension` (no content-magic nested-tar sniff).

### Tar parser integrity (required)

Reject with stable codes:

- truncated 512-byte header; invalid checksum; malformed octal/base-256 size
- body shorter than declared size; missing/invalid padding
- pax header not followed by a member; repeated pax `path` key; malformed pax length
- bytes after canonical tar EOF; wrong EOF (require **two** zero blocks)
- pax header bytes that would break uncompressed/member accounting

### Validate-before-write (required)

```text
No workspace mutation until:
- zstd frame completely validated (exact-one-frame, window, bounds)
- tar EOF validated
- every member validated (type, path, ext, utf8, secret)
- duplicates checked
- aggregate limits checked
```

Peak RSS may still be compressed + member buffers (~two × 64 MiB class). Document + add a memory-budget smoke in unit tests; do not claim decompress-bound ≡ low RSS.

### Chip filename

`taskId` is `ho_${ulid()}` — assert `/^ho_[0-9A-HJKMNP-TV-Z]{26}$/` before interpolating into `handoff-${taskId}.tar.zst`.

## Outbound contract

```typescript
archive?: {
  format: "tar.zst";
  encoding: "base64";
  data: string;   // canonical base64 of tar.zst
}
```

Mutually exclusive with non-empty `artifacts[]`. Members **upsert**. Manifest lists extracted members only.

## Exit criteria (0.9.0)

- Exactly one `.tar.zst` chip for file tasks
- Inbound E2E: >20 members + nonce quoted; chip verify = 1
- Outbound E2E: `archive` extract sha256; `artifacts[]` still works
- Bound matrix `limit-1/limit/limit+1` + members 99/100/101
- Adversarial zstd/tar/base64 matrix (incl. parser integrity) green
- Single PR merged; tag `v0.9.0`
