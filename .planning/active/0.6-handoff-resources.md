# 0.6 — Handoff Resources

**Status:** ACTIVE · **Lifecycle:** SHIP-BAR  
**Supersedes:** roadmap slots “0.6 Portable Core” + “0.7 Add Files” (consolidated)

## Goal

Allow a coding agent (Cursor) to select relevant workspace files when creating a handoff, freeze them into an **immutable task-scoped resource set**, and make them available to the ChatGPT worker.

Designed as a **resource layer**, not a ChatGPT Web upload feature.

**Core principle:** Agent chooses context; runtime chooses transport.

## Why

Today handoff transfers primarily prompt + metadata + `TASK_ID`. Files appear as path strings in `context.relevantFiles` without guaranteed delivery.

```ts
handoff_create_task({
  prompt: "Review this auth refactor for race conditions",
  files: [
    "src/auth/session.ts",
    "src/auth/token.ts",
    "tests/auth/session.test.ts",
  ],
})
```

Paths are **not** permission to browse the workspace. They are validated and snapshotted at create time.

## Architecture

```text
Cursor Agent
     │ selects files
     ▼
handoff_create_task()
     ▼
Resource Snapshot (validate → sanitize policy → immutable copy → sha256)
     ▼
Handoff Task (prompt + resource manifest)
     ▼
Worker Runtime → transport strategy
     ├─ Native Attachment (P0 production)
     ├─ MCP lazy read (partial — tool façade shipped)
     └─ context-pack / ZIP (experiments only)
     ▼
ChatGPT
```

Do **not** couple task creation to Chrome/CDP.

## Data model

**Public API** (unchanged):

```ts
handoff_create_task({ prompt, files?: string[] })
```

**Internal** (`HandoffTaskFile` / task resource):

| Field | Notes |
|-------|-------|
| `fileId` | `f_…` — public resource id (keep name; do not rename to `resourceId` in v0.6) |
| `relativePath` | Provenance only |
| `displayName` | Basename |
| `snapshotPath` | Immutable copy on disk |
| `sha256` | Of snapshotted bytes |
| `sizeBytes` | |
| `mediaType` | `text/plain` for v0.6 ship bar |

## Security boundary

**Do NOT** expose generic filesystem tools (`read_file(path)`, `shell`, `exec`, `write_file`).

Safe boundary: `handoff_read_file({ taskId, fileId })` — task-scoped only.

Pipeline at create:

```text
agent selection → workspace-root validation → traversal protection
→ denylist / secret filtering → size/type limits → snapshot
```

Fail closed: if requested resources cannot be attached safely, do not silently create a text-only task.

## P0-B — Production transport (native attach)

Inside A1-S UI-write mutex, before `TASK_ID` send:

```text
prepare task → attach resources → verify chips → send TASK_ID
```

Fail closed if resources were requested but chips cannot be verified.

| # | Item | Status |
|---|------|--------|
| 1 | CDP composer attach (`+ → Add photos & files` or `input[type=file]`) | Not started |
| 2 | Chip verification | Not started |
| 3 | Fail-closed dispatch | Not started |

## Acceptance criteria (ship bar)

1. Cursor agent can create a task with selected workspace files.
2. Files are validated and **snapshotted** at task creation.
3. Snapshot hashes and metadata persisted.
4. Task reproducible even if workspace changes afterward.
5. ChatGPT receives text/code resources via **production transport** (native attach).
6. Missing delivery fails closed.
7. No arbitrary filesystem capability for ChatGPT.
8. Text-only handoff backwards compatible.
9. Unit tests: traversal, missing files, size limits, secret-policy rejection.
10. Live E2E: at least one multi-file code handoff.
11. Worker skill / MCP instructions honor `mustReadAttachedFiles`.

## Non-goals (v0.6)

- Arbitrary repo browsing, shell/exec, workspace write
- Repo glob `**/*`, whole-repo context
- Cloud drive integration
- Binary artifact return (ChatGPT → Cursor)
- Auto transport routing
- Advanced context-selection algorithms

## Follow-up (0.8 candidate)

Symmetric artifacts on submit:

```ts
handoff_submit_result({ taskId, result, artifacts?: [...] })
```

Design resource model now so this does not require a breaking change.

## Key decisions

1. Agent chooses context.
2. Core snapshots resources.
3. Task resources are immutable after create.
4. Worker runtime chooses transport.
5. ChatGPT never gets arbitrary workspace access.
6. ZIP is packaging, not the data model.
7. Native ChatGPT attachment is the initial **production** transport for web worker.
8. MCP lazy read (`handoff_read_file`) is shipped for tool-façade path; MCP Resource primitive is experimental.

## Portable core note
