# 0.6 — Handoff Resources

**Status:** ACTIVE · **Lifecycle:** SHIP-BAR  
**Impl plan:** [0.6-handoff-resources-impl-plan.md](./0.6-handoff-resources-impl-plan.md)  
**Supersedes:** roadmap slots “0.6 Portable Core” + “0.7 Add Files”

## Goal

Agent selects workspace files → core validates + snapshotted immutable resources → runtime **guarantees delivery** to ChatGPT.

**Core principle:** Agent chooses context; runtime chooses transport.

**Production invariant:** Native attachment is the v0.6 ship bar. MCP lazy read is not a substitute. No silent fallback attach → MCP.

## Architecture

```text
handoff_create_task(files[])
  → validate + secret-content scan + snapshot
  → task manifest

worker claim
  → PREPARING_RESOURCES (attach via file input)
  → RESOURCES_VERIFIED (per-file chip match)
  → DISPATCH_FENCED (markDispatchStarted)
  → TASK_ID_SENT
```

See [ADR-004](../decisions/ADR-004-dispatch-fence-vs-attachment.md) for fence placement.

## Data model

Public: `files?: string[]` on create.

Internal `HandoffTaskFile`: `fileId`, `relativePath`, `displayName`, `snapshotPath`, `sha256`, `sizeBytes`, `mediaType`.

**Duplicate basenames:** reject at create if two `files[]` resolve to the same `displayName` (`FILES_DUPLICATE_BASENAME`). No transport-side rename in v0.6.

## Security pipeline (create)

```text
agent selection
  → workspace-root validation
  → traversal / symlink reject
  → extension + filename denylist
  → duplicate basename reject
  → secret-content scan (reuse SECRET_PATTERNS) → FILES_SECRET_DETECTED
  → size limits (10 files, 256KB/file, 1MB/task)
  → snapshot
```

Read-time `sanitizeSecrets()` remains for MCP path (defense in depth).

## Limits (unchanged v0.6)

```text
10 files · 256 KB/file · 1 MB/task · text/code extensions only
```

Dataset “30 × 20 KB” is for post-0.6 transport experiments, not acceptance.

## P0-B — Native attachment (production)

All remaining work lands in **one PR** (`feat/0.6-handoff-resources`). Phases A–D in [impl plan](./0.6-handoff-resources-impl-plan.md).

**Priority:** `input[type=file]` + `setInputFiles(snapshotPaths)` first. Menu fallback only.

### PrepareResult + chip verification (Phases B–C)

Not `verified: boolean`. Use structured result:

```ts
type PrepareResult =
  | { ok: true; attached: PreparedResource[] }
  | {
      ok: false;
      expected: string[];
      observed: string[];
      reason:
        | "INPUT_NOT_FOUND"
        | "UPLOAD_TIMEOUT"
        | "CHIP_MISMATCH"
        | "UPLOAD_REJECTED";
    };
```

### Chip verification

Per-resource match — **not** `attachedCount >= files.length` (see impl plan).

### Worker + E2E (Phases C–D)

Native-only proof:

```text
file contains ATTACH_E2E_NONCE = "native_attach_7F4D92A1"
prompt: return nonce; do not call handoff_read_file
assert: result contains nonce; MCP read not invoked
multi-file (≥2) with distinct basenames
```

## Acceptance criteria (ship bar)

1.–4. Snapshot + manifest (done).
5. Native attach delivers resources; **not** MCP-read-only pass.
6. Fail-closed on attach failure — no silent downgrade.
7. No arbitrary filesystem MCP.
8. Text-only handoff unchanged.
9. Unit tests incl. secret-content + duplicate basename.
10. Native-only E2E with nonce (≥2 files).
11. Worker skill documents attach path; E2E forbids MCP read for production proof.

## Non-goals

Silent attach→MCP fallback · context-pack before CDP · auto transport routing · ZIP default · bump file limits · CI/CD as competing “0.6 product version” (engineering track separate)
