# v0.8 — Native Writeback (Result Artifacts) — Spec

**Status:** ACCEPTED (2026-09-02) · **Branch:** `feat/0.8-writeback`  
**Authoritative impl:** `src/tasks/result-artifacts.ts`, `handoff_submit_result` MCP tool  
**ADR:** ADR-010-native-writeback (Phase E)

---

## 1. Problem

Today ChatGPT returns handoff results as **prose only**. Cursor must parse text to learn what changed. v0.8 adds **native writeback**: structured file delivery ChatGPT → workspace, symmetric to v0.7 inbound attach.

---

## 2. User model

| Expectation | v0.8 spec |
|-------------|-----------|
| ChatGPT **sửa file có sẵn** | ✅ `artifacts[]` + `mode: "overwrite"`, workspace-relative path |
| ChatGPT **tạo file mới** | ✅ `artifacts[]` + `mode: "create"` (default) |
| Trả **files thật** trên disk | ✅ Server materializes bytes → manifest in `get_result` |
| **Quá nhiều files** → zip | ⏸ **0.8.1+** |
| **Không có complete final content** → text only | ✅ Field `result` (prose); Cursor agent apply locally |

**Key rule (revised):** **Large ≠ partial.** A large file is valid for writeback if the worker can provide the **complete final UTF-8 body** within caps (32 MiB/file, 128 MiB total). Prose-only applies when the worker **cannot** safely represent the change as a complete final file — not because the file is large per se.

---

## 3. Contract layers

| Layer | Role | Enforced by |
|-------|------|-------------|
| **Schema** | Structural contract: `artifacts[]`, `path`, `content`, `mode`, `maxItems: 20` | MCP Zod input schema |
| **Runtime** | Semantic contract: path safety, byte caps, secret scan, state-dependent rules, batch commit + rollback | `writeResultArtifacts()` |
| **Tool description** | Capability visible to model: full-content requirement, modes, limits, batch semantics | `SUBMIT_RESULT_TOOL_DESCRIPTION` |
| **Per-task guidance** | Behavioral decision tree | `handoff_get_task.submitPolicy.writeback` |
| **Spec / ADR** | Full normative semantics + failure model | This doc + ADR-010 |

**Do not duplicate** path traversal, extension allowlist, secret patterns, temp/rename/rollback implementation in worker policy — runtime is source of truth for those.

## 4. Transport contract (v0.8.0)

### 4.1 `handoff_submit_result` (input)

```typescript
{
  taskId: string;           // required
  result: string;           // required — always non-empty
  metadata?: {
    summary?: string;
    confidence?: "low" | "medium" | "high";
  };
  artifacts?: Array<{       // optional — ChatGPT → server
    path: string;           // workspace-relative POSIX
    content: string;        // full UTF-8 file body (NOT a diff)
    mode?: "create" | "overwrite";  // default "create"
  }>;
}
```

### 4.2 Output (`handoff_get_result`)

Server populates manifest in `metadata.artifacts`:

```typescript
metadata.artifacts?: Array<{
  relativePath: string;
  displayName: string;
  sizeBytes: number;
  sha256: string;
}>;
```

### 4.3 Runtime invariants (`writeResultArtifacts`)

| Guard | Behavior |
|-------|----------|
| Extension allowlist | Shared with v0.7 inbound attach |
| Secret filename / content | Full-body scan (≤32 MiB); reject on match |
| Size | ≤ 32 MiB/file, ≤ 128 MiB total per submit |
| Count | ≤ **20** artifacts per submit |
| Encoding | UTF-8 text; reject NUL in first 8 KiB |
| `create` | Fail if target exists (`wx` / create-if-absent) |
| `overwrite` | Atomic replace (temp → rename) |
| **Batch semantics** | See §4.4 |

### 4.4 Transaction semantics (pragmatic v0.8 — confirmed 2026-09-02)

**Model-facing contract:**

> The batch is validated as a unit. **Validation failures write nothing.** If a handled commit fails, the server **rolls back** writes made by that batch before returning an error.

**Not guaranteed in v0.8.0** (documented in ADR-010):

- Process crash mid-commit
- Rollback itself failing (disk error, permissions)
- Hostile concurrent filesystem mutation outside server control

Do **not** promise absolute filesystem transactions ("none take effect under all failure modes") unless implementation upgrades to journal/snapshot — out of scope for v0.8.0.

**Task state:** Any artifact error → entire submit rejected; task stays non-COMPLETED.

## 5. MCP writeback contract (model guidance)

### 5.1 Decision tree (`submitPolicy.writeback`)

```text
Can produce complete final file content within limits?
    |
    +-- no  --> result prose only (no artifact)
    |
    +-- yes
          |
          +-- existing/attached path --> mode=overwrite
          |
          +-- new path ---------------> mode=create
```

### 5.2 `WRITEBACK_POLICY` (compact, decision-oriented)

```typescript
export const WRITEBACK_POLICY = {
  whenToWrite: [
    "Write an artifact only when you can provide the complete final file content.",
    "For an attached/existing workspace file, use mode=overwrite.",
    "For a new workspace path, use mode=create.",
    "If the change cannot be safely represented as a complete final file, do not emit an artifact; describe it in result instead.",
  ],
  submission: [
    "Artifacts are validated and committed as one batch. Validation failures write nothing.",
    "If a commit fails, the server rolls back that batch before returning an error.",
    "Always provide a non-empty result summarizing files written and any prose-only changes.",
  ],
  onRejection: [
    "If artifact submission is rejected, assume no artifact from that batch was accepted.",
    "Correct the reported problem and retry only if it can be corrected safely.",
    "On create collision (target exists): do NOT automatically switch to overwrite — report conflict or use prose-only.",
  ],
} as const;
```

**Caps are not duplicated here** — schema + tool description state limits; runtime enforces.

### 5.3 Tool description (capability, not mini-spec)

Concise `SUBMIT_RESULT_TOOL_DESCRIPTION` covering:

- Full final content requirement (not partial patches)
- `overwrite` vs `create`
- Batch validation + rollback semantics (observable, not implementation)
- Limits: 20 artifacts, 32 MiB/file, 128 MiB total
- `result` always non-empty

No path/secret/extension rules. No temp/rename details. **No examples in v0.8.0** unless E2E shows systematic misuse.

### 5.4 Error contract (MCP)

| Error class | Delivery | Examples |
|-------------|----------|----------|
| Correctable validation/business | Tool result `isError: true` + safe code + path/index | `FILES_INVALID`, `FILE_TOO_LARGE`, `FILES_SECRET_DETECTED`, create collision |
| Unexpected internal / I/O | Generic server/tool failure | `ARTIFACT_WRITE_FAILED` |

- Never expose artifact content or secrets in error text.
- Never instruct model to convert create collision → overwrite retry.

**Current gap:** `handoff_submit_result` returns success JSON or throws; `isError: true` not yet implemented. Phase 3A.

### 5.5 MCP annotations (optional, nice-to-have)

```typescript
readOnlyHint: false,
destructiveHint: true,   // overwrite mutates existing data
idempotentHint: false,    // create second call ≠ first
openWorldHint: false,     // local workspace only
```

Annotations are hints only — not security enforcement. **Current code incorrectly has `idempotentHint: true` and `destructiveHint: false`** — fix in Phase 3C.

## 6. Cursor-side consumption

After stop hook resume:

1. `handoff_get_result` → `result` + `metadata.artifacts`
2. Open files at `workspaceRoot/relativePath` (bytes on disk)
3. Prose-only changes in `result` → agent applies via edit tools

**No new Cursor MCP read tool for P0.**

`result` should distinguish **written artifacts** vs **prose-only/unchanged** files (human-readable; machine-readable list is nice-to-have, not P0).

## 7. Example scenarios

### A — Overwrite 2 attached files (happy path)

```json
{
  "result": "Written: src/a.ts, src/b.ts.",
  "artifacts": [
    { "path": "src/a.ts", "content": "...full...", "mode": "overwrite" },
    { "path": "src/b.ts", "content": "...full...", "mode": "overwrite" }
  ]
}
```

### B — Create new file

```json
{
  "result": "Written: src/lib/new-helper.ts.",
  "artifacts": [
    { "path": "src/lib/new-helper.ts", "content": "export function helper() {}\n" }
  ]
}
```

### C — Cannot produce complete content (prose only)

```json
{
  "result": "Prose-only: In src/huge.ts lines 1204-1209 replace OLD with NEW (full file not reproduced).",
  "artifacts": []
}
```

### D — Create collision

Submit with `mode: create` on existing path → `FILES_INVALID` / create-target-exists → **do not** retry as overwrite; report in `result`.

### E — >20 files

Top **20** in `artifacts[]`; remainder in `result`. ZIP deferred 0.8.1+.
