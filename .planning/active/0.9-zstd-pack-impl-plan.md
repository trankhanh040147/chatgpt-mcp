## Contract summary

```text
Inbound:
  files[] (≤100) → materializeForArchivePack → packTarPax → zstd (1 frame, window ≤8MiB)
    → setInputFiles([handoff-{taskId}.tar.zst]) → verify exactly 1 chip

Outbound:
  handoff_submit_result({
    taskId, result,
    artifacts?: [...],   // v0.8 unchanged
    archive?: { format:"tar.zst", encoding:"base64", data }  // XOR artifacts
  })
```

**Caps (pack):** 100 · 64 MiB/member · 64 MiB uncompressed · 64 MiB compressed · `MAX_ZSTD_WINDOW=8MiB` **including single-segment FCS**.  
**`artifacts[]`:** 20 / 32 / 128 unchanged.

### Zstd window (normative — review fix)

```text
if singleSegment:
    require FCS
    require FCS <= MAX_UNCOMPRESSED_BYTES
    require FCS <= MAX_ZSTD_WINDOW      # 8 MiB — same as window
else:
    require Window_Size <= MAX_ZSTD_WINDOW
```

Producer: **windowed** frames for packs whose tar stream may exceed 8 MiB.

## Phase 0 — Capability spike + fixtures (security gate)

### 0A — Zstd dependency spike (must pass before locking)

“Compress/decompress works” is **not** enough. Spike must prove the chosen API can:

```text
- inspect frame type / exact frame boundary / bytes consumed
- read windowSize, frameContentSize, dictionary ID
- enforce streaming output limit (abort before byte 64MiB+1)
- set or verify compression windowLog / Window_Size ≤ 8 MiB
- reject WITHOUT decompress-all-first:
    huge window, skippable frame, concatenated second frame, trailing garbage,
    dictID != 0
```

| Choice | When |
|--------|------|
| **A. `node:zlib` zstd** | Exposes header/stream controls above |
| **B. Native binding (e.g. `@mongodb-js/zstd` + header parse, or `zstd-napi`)** | Need `ZSTD_getFrameHeader`-class info |
| **C. WASM (`fzstd`) alone** | Only if spike proves bound + multi-frame reject; prefer A/B |

**Exit 0 fails** if the only available API is `decompress(buf) → buf` with no frame inspection.

Record winner in ADR-011 “Implementation notes” in this PR.

Tar: **hand-roll** minimal pax writer/reader (regular + `'x'`). Avoid auto-extract-to-disk libraries.

### 0B — Fixtures

Helper builds valid tiny tar.zst + bound/adversarial cases listed in Phase 1 tests.

### Exit 0

- Spike script/test proves reject huge-window / skippable / concat / trailing **without** full decompress-first
- Dep chosen; ADR-011 implementation notes filled
- `typecheck` green with archive stubs

## Phase 1 — Core codec (unit-first)

### 1A–1D

Constants, `ArchiveError` taxonomy, canonical base64 **with encoded-length preflight**, zstd compress/decompress per window rule, tar pax pack/parse with:

**Parser state machine + EOF contract:**

- truncated header; bad checksum; malformed size; short body; bad padding
- pax not followed by member; repeated `path`; malformed pax length; pax path empty/NUL
- require **two** zero EOF blocks; reject trailing non-zero after EOF
- pax header included in uncompressed accounting

### Validate-before-write invariant (ingest uses later)

```text
No workspace mutation until zstd + tar EOF + all members + dupes + aggregates + secrets OK
```

Design note: peak RSS may be compressed buffer + member Buffers (~2×64 MiB class). Add a memory-budget smoke (assert process doesn’t allocate decoded buffer for preflight-failing base64).

### 1E — Tests (`scripts/test-archive-codec.ts`)

**Bounds:** compressed / uncompressed / member `limit-1|limit|limit+1`; members 99/100/101.

**Zstd:** no FCS; huge window; 2 frames; skippable; trailing 1 byte; truncated; dictID≠0; checksum corruption; FCS≤limit but stream disagrees; single-segment FCS 8MiB+1 → `ARCHIVE_ZSTD_WINDOW_TOO_LARGE`.

**Tar:** bad checksum; truncated header/body; malformed pax length; pax without member; pax path="" / NUL; duplicate after pax override; trailing after EOF; one zero block only; hardlink/symlink/dir/sparse; `.zip` extension.

**Base64:** non-canonical; impossible padding; decoded exactly limit; **encoded preflight > limit without allocating decoded buffer**.

**Pack:** incompressible → `PACK_COMPRESSED_TOO_LARGE`.

### Exit 1

All codec adversarial + parser-integrity tests green. **This is the security gate** — do not wire worker/MCP until Exit 1.

## Phase 2 — Inbound always-one-chip

### 2A — Create

`registerTaskResourcePaths`: remove `FILES_DUPLICATE_BASENAME`; max 100 paths.  
MCP `files` `.max(100)`. Update `test-files.ts`.

### 2B — Materialize caps (explicit API)

Do **not** silently change shared `MAX_BYTES_PER_FILE` / `MAX_BYTES_PER_TASK` (32/128 for `artifacts[]`).

```typescript
materializeResourcesForArchivePack(resources, root)
// or materializeWorkspaceResources(resources, root, {
//   maxMemberBytes: MAX_MEMBER_BYTES,
//   maxTotalBytes: MAX_UNCOMPRESSED_BYTES,
// })
```

Today only `worker.ts` calls materialize — still use explicit pack path so future callers don’t inherit 64/64 by accident.

**GitNexus** before edit: `impact` on `materializeWorkspaceResources`, `registerTaskResourcePaths`.

### 2C — Pack + attach

`packPreparedAsTarZst(prepared, taskId)`:

- Assert `taskId` matches `/^ho_[0-9A-HJKMNP-TV-Z]{26}$/`
- Name `handoff-${taskId}.tar.zst`, `mimeType: application/zstd`
- Windowed zstd; `PACK_COMPRESSED_TOO_LARGE` if needed

`worker.ts`: materializeForArchive → pack → `prepare([one])`.  
Chip verify: expected length 1 (large-batch multiset path N/A).

### 2D — Prompt

Worker policy: evidence is one tar.zst; member paths are tar paths.

### 2E — Tests / E2E

Update attach-lifecycle / attachment-match.  
Live: ≥25 members + nonce; chip count 1; model quotes nonce.

### Exit 2

Production file tasks never multi-chip; inbound E2E green.

### 3A — MCP schema

### 3E — Tests / E2E

`test-archive-ingest`, extend `test-writeback-contract`, live `e2e-archive-writeback`.

### Exit 3

Outbound unit + live green; artifacts path unbroken.
